# Changelog

## [Unreleased]

### Added
- Scheduled runs and an archive (#4): `unattended` runs ask nothing, use saved profiles with `--since-last-run`, publish nothing except an optional `notify=<owner/repo>#<issue>` comment, and archive the report; `weekly` reads 7 days and compares topics with the previous weekly report. `scripts/archive.php` saves reports as `<YYYY-MM-DD>-<name>[-weekly].md` with their fetch data and never overwrites (`-2`, `-3` …); `fetch.php` adds `topic_counts`. `docs/scheduling.md` with ready-made cron, launchd and Task Scheduler files, and the limits of a cloud routine.
- Proposals to GitHub issues (#5): on request ("založ issues pro P1 a P3") the skill checks for an existing issue on the proposal and for similar titles in the repository, drafts each issue from the new `templates/issue.md` with the dev-null source links, shows a preview, creates nothing without explicit confirmation, creates the issues with `gh issue create --body-file` (optional label `from-devnull`), and stores each issue link on its proposal.
- Memory between runs (#3): `scripts/state.php` keeps a per-profile `state/<profile>.json` with the last run, the reported posts (forgotten after 30 days), and proposals with stable IDs and a status (`new`, `accepted`, `done`, `rejected`). `fetch.php --profile` leaves reported posts out (`filtered_out.already_seen`, `--include-seen` keeps them), lists the known proposals per project, and `--since-last-run` reads only the time since the last recorded run (at most 7 days). The skill reinforces earlier proposals instead of repeating them, keeps rejected ones out unless a clearly stronger signal appears, registers new proposals before the report, and records the run after it. Merged series remember the ids of all their posts (`series_ids`).
- Project profiles (#2): `scripts/profiles.php` saves, lists, shows and removes profiles (repository, strong / weak / excluded keywords, topics, hours) in a per-user `projects.json` (Windows `%APPDATA%`, XDG, or `~/.config`; `DEVNULL_INSIGHTS_HOME` overrides). `fetch.php --profile=name[,name]|all` reads the log once and selects each profile's posts with its own settings; replies of a post listed by several projects are loaded once. The skill uses a saved profile without questions, runs all projects on request, and proposes a profile after the first report for a new repository.
- Noise suppression (#1): topics have `strong` and `weak` keywords; weak-only matches are dropped, and a strong keyword found only in a link preview or quoted post counts as weak. Each matched post carries a relevance `score`, filtered by `--min-score`. Series of near-identical posts by one author are merged (`series_count`). The output reports `filtered_out` with the reasons. New options `--weak-keywords` and `--min-score`. On the live 24 h log with the ai-olympus keywords, matches dropped from 143 to 60 (58 %) and every post the ai-olympus report cited stayed.
- Tests and CI: Pest suite with a `php -S` fixture server standing in for dev-null.sh, a portability scan of the plugin scripts, a CI matrix on Ubuntu, macOS and Windows × PHP 8.3–8.5 with manifest validation, and a daily contract smoke test against the live site that opens an issue on failure (#6).
- `templates/report.md`: one Markdown report layout for every request (repository, digest and question modes) — header table, TL;DR, theme and proposal tables with stable IDs, quick-win checklist, engagement table, method and limits.

### Changed
- `fetch.php` is split into small classes under `scripts/src` with its own autoloader (no Composer at runtime). Every dev-null.sh response is checked against the expected shape: a changed shape, an unreachable site or an invalid option ends the run with exit code 1 and an `error:` line, never with an empty result. A version change during the run is followed, and a failed replies request is reported as `replies_error` on the post (#6).
- Every output item (themes, proposals, quick wins, engagement opportunities, quotes) must link its source dev-null post as `[@author](url)`, with the URL taken verbatim from the fetched JSON; items without a source post are dropped.
- `fetch.php` runs unchanged on Windows, macOS and Linux: HTTPS through PHP streams instead of ext-curl, case-insensitive regex instead of ext-mbstring, new `--output` option instead of shell redirection (Windows PowerShell 5.1 writes UTF-16).
- The skill reads the target README via `gh api … -H "Accept: application/vnd.github.raw"` instead of the Unix-only `base64 -d`.

## [0.1.0] - 2026-11-10

### Added
- `devnull-insights` plugin and skill: scans the public dev-null.sh log for a time window, filters posts by topics and repository keywords, loads discussion replies, and proposes evidence-backed repository improvements.
- Marketplace manifests for Claude Code (`.claude-plugin/marketplace.json`) and Codex (`.agents/plugins/marketplace.json`).
